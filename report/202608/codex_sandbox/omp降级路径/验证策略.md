## 3. 分步实验

### V1：三种用法都能直接降级（C1）

```bash
mkdir -p $OUT
$TOOLS/mlir-translate --mlir-to-llvmir -o $OUT/v1_mlir_translate.ll $SRC
$TOOLS/tco -O0 -o $OUT/v1_tco_default.ll $SRC
$TOOLS/tco --code-gen-llvm -o $OUT/v1_tco_codegen.ll $SRC
```

- 预期：三个退出码均为 0；产物含 `__kmpc_fork_call`、`__kmpc_for_static_init_4u`。
- 判定：`rg -c '__kmpc_fork_call' $OUT/v1_*.ll` 均 ≥ 1。
- 源码对照：`flang/tools/tco/tco.cpp:139`（`parseSourceFile<ModuleOp>`）、
  `mlir/lib/Target/LLVMIR/ConvertToLLVMIR.cpp:25`（`mlir-to-llvmir` 注册）。

### V2：产物一致性（C2）

```bash
diff $OUT/v1_tco_default.ll $OUT/v1_tco_codegen.ll          # 应为空
diff $OUT/v1_tco_default.ll /home/wangyz/test/openacc/parallel_do/parallel_do.f90.ll   # 应为空
diff <(sed '1,2d' $OUT/v1_mlir_translate.ll) <(sed '1,2d' $OUT/v1_tco_default.ll)     # 应为空
head -2 $OUT/v1_mlir_translate.ll   # ModuleID = 'LLVMDialectModule'
head -2 $OUT/v1_tco_default.ll      # ModuleID = 'FIRModule'
```

- 预期：tco 两路与原始 `.ll` 完全一致；mlir-translate 仅前两行模块名不同。
- 判定：前三个 diff 无输出；两个 head 的 `ModuleID` 分别是 `LLVMDialectModule` 与 `FIRModule`。
- 源码对照：`mlir/include/mlir/Target/LLVMIR/Export.h:29`（默认名 `LLVMDialectModule`）、
  `flang/lib/Optimizer/CodeGen/CodeGen.cpp:4433`（`"FIRModule"`）。

### V3：解析期字符串→类型匹配（C3）

```bash
# 负向：改 op 名，解析器查表失败
sed 's/omp\.parallel/omp.parallelx/' $SRC | $TOOLS/mlir-translate --mlir-to-llvmir - 2>&1 | head -3
```

- 预期报错：`custom op 'omp.parallelx' is unknown`（✅ 已实测）。
- 判定：出现该文案，且报错位置指向被改的行。
- 源码对照：
  - `mlir/lib/AsmParser/Parser.cpp:2006`（`parseCustomOperationName`，先查表后加载 dialect）；
  - `mlir/lib/IR/MLIRContext.cpp:953`（`RegisteredOperationName::lookup`）；
  - `mlir/lib/Dialect/OpenMP/IR/OpenMPDialect.cpp:307`（`addOperations<GET_OP_LIST>` 建表）。

### V4：第一层按 dialect 路由（C4）

```bash
# 负向：无翻译接口的 op
printf 'module { "foo.bar"() : () -> () }\n' | \
  $TOOLS/mlir-translate --mlir-to-llvmir --allow-unregistered-dialect - 2>&1 | head -3
```

- 预期报错：`cannot be converted to LLVM IR: missing LLVMTranslationDialectInterface
  registration for dialect for op: foo.bar`（✅ 已实测）。
- 判定：文案命中 [ModuleTranslation.cpp:996](//home/wangyz/.llvm/llvm-project/mlir/lib/Target/LLVMIR/ModuleTranslation.cpp:996) 的报错分支。
- 源码对照：`mlir/include/mlir/Target/LLVMIR/LLVMTranslationInterface.h:78`
  （`LLVMTranslationInterface` = 接口集合）、`mlir/include/mlir/IR/DialectInterface.h:170`
  （`getInterfaceFor`）。

### V5：第二层按 op 类型分派（C5）

```bash
# 正向：把 omp.parallel 换成 omp.sections，观察 runtime 调用变化（TypeSwitch 分支切换）
sed -e 's/omp\.parallel {/omp.sections {/' -e 's/omp\.terminator/omp.terminator/' $SRC \
  | $TOOLS/mlir-translate --mlir-to-llvmir - 2>&1 | rg '__kmpc_' | sort -u
```

- ⬜ 未实测：预期 `__kmpc_fork_call` 仍出现，但 worksharing 初始化函数由
  `__kmpc_for_static_init_4u` 变为 sections 相关调用（具体以实际输出为准，记录到表里）。
- 判定：函数集合与 V1 产物不同，证明换 op 类型换了处理函数。
- 源码对照：[OpenMPToLLVMIRTranslation.cpp:6866](//home/wangyz/.llvm/llvm-project/mlir/lib/Target/LLVMIR/Dialect/OpenMP/OpenMPToLLVMIRTranslation.cpp:6866)
  的 `TypeSwitch`：`omp::ParallelOp → convertOmpParallel`、
  `omp::SectionsOp → convertOmpSections`。

### V6：第三层按语义参数选 runtime 函数（C6）

```bash
# 模板 A：i32 循环（默认用 parallel_do.f90.mlir）
$TOOLS/mlir-translate --mlir-to-llvmir -o $OUT/v6_i32.ll $SRC
rg -o '__kmpc_for_static_init_[0-9a-z]+' $OUT/v6_i32.ll | sort -u

# 模板 B：i64 循环（已备好 out/v6_loop_i64.mlir）
$TOOLS/mlir-translate --mlir-to-llvmir -o $OUT/v6_i64.ll $OUT/v6_loop_i64.mlir
rg -o '__kmpc_for_static_init_[0-9a-z]+' $OUT/v6_i64.ll | sort -u
```

- 预期：i32 → `__kmpc_for_static_init_4u`；i64 → `__kmpc_for_static_init_8u`（✅ 已实测）。
- 判定：两个后缀分别是 `4u` 与 `8u`（IVSize 32/64，无符号 u）。
- 源码对照：[OMPIRBuilder.cpp:8051](//home/wangyz/.llvm/llvm-project/llvm/lib/Frontend/OpenMP/OMPIRBuilder.cpp:8051)
  `createForStaticInitFunction(IVSize, IVSigned)`；wsloop 内调用点
  [OpenMPToLLVMIRTranslation.cpp:3059](//home/wangyz/.llvm/llvm-project/mlir/lib/Target/LLVMIR/Dialect/OpenMP/OpenMPToLLVMIRTranslation.cpp:3059)
  `applyWorkshareLoop`。
- 可选扩展：给 wsloop 加 `schedule(dynamic)` / `nowait` 属性，预期出现
  `__kmpc_dispatch_init_*` / 消失 `__kmpc_barrier`（手工改属性易触发 verify 报错，
  建议用 flang 源文件 + 对应指令生成）。

### V7：Conversion 只做类型化重写（C7）

```bash
$TOOLS/mlir-opt --convert-openmp-to-llvm $OUT/v7_loop_index.mlir -o $OUT/v7_after.mlir
head -20 $OUT/v7_after.mlir
```

- 预期（✅ 已实测）：`func.func` → `llvm.func`、`arith.constant` →
  `llvm.mlir.constant`、`omp.loop_nest (%arg0) : index` → `: i64`；
  **`omp.parallel` / `omp.wsloop` / `omp.loop_nest` 原样保留**。
- 判定：输出里仍能找到 `omp.parallel`，且 iv 类型从 `index` 变为 `i64`。
- 源码对照：[OpenMPToLLVM.cpp:41](//home/wangyz/.llvm/llvm-project/mlir/lib/Conversion/OpenMPToLLVM/OpenMPToLLVM.cpp:41)
  `OpenMPOpConversion<T>`（`T::create` 重建同名 op，region 原地保留）、
  [OpenMPToLLVM.cpp:122](//home/wangyz/.llvm/llvm-project/mlir/lib/Conversion/OpenMPToLLVM/OpenMPToLLVM.cpp:122)
  （动态合法条件 = 类型已 LLVM 化）。

### V8：两条路线汇合（C8）

```bash
$TOOLS/mlir-translate --mlir-to-llvmir -o $OUT/v8.ll $OUT/v7_after.mlir
rg -c '__kmpc_fork_call|__kmpc_for_static_init' $OUT/v8.ll
```

- 预期（✅ 已实测）：退出码 0，产物含 `__kmpc_fork_call` 等 runtime 调用。
- 判定：`rg -c` 结果 ≥ 1，证明 Conversion 产物最终仍靠
  `translateModuleToLLVMIR` 直译才能出 `.ll`。
- 源码对照：`mlir/lib/Target/LLVMIR/ModuleTranslation.cpp:2383`（翻译总入口）；
  对照图 [openmp_conversion.png](openmp_conversion.png) 底部。

## 4. 通过/失败判据汇总

| 实验 | 通过判据 | 失败表现 |
|---|---|---|
| V1 | 三个退出码 0，产物含 `__kmpc_*` | 任一步非 0 / 产物无 runtime 调用 |
| V2 | 三个 diff 为空；ModuleID 如预期 | 有差异（先看是否只是模块名） |
| V3 | 报 `custom op '...' is unknown` | 解析成功（说明注册表行为不符） |
| V4 | 报 `missing LLVMTranslationDialectInterface` | 翻译成功 / 其他报错 |
| V5 | `__kmpc_*` 集合与 V1 不同 | 无变化（TypeSwitch 未分派） |
| V6 | `_4u` vs `_8u` 对应 i32/i64 | 后缀与 IV 类型不符 |
| V7 | omp op 保留且类型变 `i64` | omp op 消失或类型未变 |
| V8 | 退出码 0，产物含 `__kmpc_*` | 转换失败（产物未完全 LLVM 化） |

## 7. 风险与注意事项

1. **行号会漂移**：文档中行号取自 2026-08-22 本地仓库，改版本后以 `rg` 重新定位。
2. **写权限**：`/home/wangyz/test/` 在工作区之外，验证输出统一放
   `codex_sandbox/omp降级路径/out/`，避免审批依赖。
3. **手工改 IR 易触发 verify**：V6 可选扩展建议用 flang 源文件生成，不要手改属性。
4. **模板文件**：`out/v6_loop_i64.mlir`、`out/v7_loop_index.mlir` 为最小复现样例，
   后续验证可直接复用。
5. **两条路线并存**：判断某流程走哪条，看入口（`mlir-translate`/`tco` = 直译；
   `mlir-opt` + pass = Conversion），以及 `ls mlir/lib/Target/LLVMIR/Dialect/<Name>/` vs
   `ls mlir/lib/Conversion/<Name>ToLLVM/`。
