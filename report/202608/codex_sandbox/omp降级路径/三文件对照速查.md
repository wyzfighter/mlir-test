# 三份测试文件对照速查

> 定位：`parallel_do`（OpenMP worksharing）、`target`（OpenMP offload）、`try`
> （OpenACC 组合构造）三份 final-mlir 的“一页对照”。详细逐行解释见文末链接。

---

## 0. 基本信息

| 项 | parallel_do | target | try |
|---|---|---|---|
| 路径 | `test/openacc/parallel_do/parallel_do.f90.mlir` | `test/openacc/omp-target/target.f90.mlir` | `test/openacc/acc_loop/try.f90.mlir` |
| 源码构造 | `!$omp parallel do` | `!$omp target map(to:n) map(from:a)` | `!$acc parallel loop` |
| 行数（快照 08-22） | 30 | 56 | 38 |
| 方言 | OpenMP + LLVM | OpenMP + LLVM | **OpenACC** + LLVM/FIR |
| 核心 op | `omp.parallel` / `omp.wsloop` / `omp.loop_nest` | `omp.target` / `omp.map.info` / `omp.map.bounds` | `acc.parallel` / `acc.loop` / `acc.private.recipe` |

## 1. 模块属性差异

| 属性 | parallel_do | target | try |
|---|---|---|---|
| `dlti.dl_spec` / `fir.defaultkind` / `fir.kindmap` / `llvm.*` | ✅ | ✅ | ✅（无 omp 项） |
| `omp.is_gpu` / `omp.is_target_device` / `omp.target_triples` / `omp.version` | ✅ | ✅ | — |
| `omp.requires` | — | ✅ `#omp<clause_requires none>` | — |

`omp.requires` 只出现在 target 文件；acc 文件没有任何 `omp.*` 模块属性。

---

## 2. 私有化机制

| | parallel_do | try |
|---|---|---|
| 声明 | `omp.private {type = private} @_QFEi_private_i32 : i32` | `acc.private.recipe @privatization_ref_i32 : !fir.ref<i32> init {...}` |
| 使用点 | `omp.wsloop private(@_QFEi_private_i32 %1 -> %arg0)` | `acc.loop private(%6)` + `acc.private varPtr(...) recipe(...) {implicit=true}` |
| 形态 | 纯 `!llvm.ptr` | `!fir.ref` 与 `!llvm.ptr` 混用，靠 `builtin.unrealized_conversion_cast` 桥接 |

target 文件没有显式 private（`i` 走 `omp.map.info map_clauses(implicit) capture(ByCopy)`）。

---

## 3. 循环结构

| | parallel_do | target | try |
|---|---|---|---|
| 循环 op | `omp.wsloop` + `omp.loop_nest (%arg1) : i32 = (1) to (100) inclusive step (1)` | **无 omp 循环 op**：普通 CFG（`llvm.br/cond_br` + PHI） | `acc.loop control(%arg0 : i32) = (1) to (100) step (1)` |
| 上界来源 | 常数 100（`n` 已折叠） | `load %arg0`（设备端 `n`） | 常数 100 |
| 终止符 | `omp.yield` / `omp.terminator` | `omp.terminator` | `acc.yield` |
| 附加属性 | — | — | `inclusiveUpperbound=[true]`、`independent=[none]` |

为什么 target 里没有 `omp.loop_nest`：target 区域内是普通 `do`（无 worksharing），
flang 直接生成 CFG 循环。

---

## 4. 组合/嵌套标记

| | parallel_do | target | try |
|---|---|---|---|
| 构造嵌套 | 普通嵌套（`parallel` 包 `wsloop` 包 `loop_nest`），无 `omp.composite` | target 包 CFG | **组合构造**：`acc.parallel combined(loop)` + `acc.loop combined(parallel)` 互指 |

OpenMP 的组合标记是 `omp.composite` 属性（`isComposite()` 检查）；本示例是普通嵌套。
OpenACC 用 `combined(...)` 显式互指。

---

## 5. 降级出口

| | parallel_do | target | try |
|---|---|---|---|
| 翻译函数族 | `convertOmpParallel` / `convertOmpWsloop` / `convertOmpLoopNest` | `convertOmpTarget` + map 翻译（`convertOmpTargetData` 族） | OpenACC 翻译/acc 转换（`acc_*` runtime） |
| 产物特征 | `__kmpc_fork_call` + `__kmpc_for_static_init_4u` + barrier | `__tgt_target_*` + map 参数表（offload） | `acc_parallel_*` / `acc_loop` runtime 调用 |
| iv 类型 → 函数名 | `i32` 无符号 → `_4u` | —（无 worksharing init） | — |

---

## 6. 一句话记忆

- **parallel_do**：worksharing 代表——`parallel` outline + `wsloop` 静态调度分发；
- **target**：offload 代表——`map.info/bounds` 描述数据搬移，`target` 内普通循环；
- **try**：OpenACC 组合构造代表——`combined()` 互指 + recipe 私有化 + 类型混存
  （`unrealized_conversion_cast` 说明处于 codegen 中间态）。
